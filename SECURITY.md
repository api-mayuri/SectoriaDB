# Безопасность

## Поддерживаемые версии

| Версия | Исправления безопасности | Исправления ошибок |
|---|---|---|
| 1.0.x (с `1.0.0-rc.1`) | да | да |
| сборки этапов `01-…`–`24-…` (до 1.0) | нет — обновитесь до 1.0 | нет |

- Исправления выходят как новые версии `1.0.x` поверх последней; ветка 1.0 поддерживается, пока не выйдет 1.1, и ещё 6 месяцев после — только безопасность.
- Обновление внутри 1.x не требует перезаливки данных: формат хранилища мигрирует при старте ([operations.md](docs/guide/operations.md#обновление)).
  Перед обновлением делайте снимок тома: откат на старшую версию после миграции — только из него.
- Отдельных бэкпортов на сборки этапов нет: каждая из них — промежуточное состояние разработки.

## Как сообщить об уязвимости

**Не открывайте публичный issue.** Сообщите через приватный отчёт GitHub: вкладка **Security → Report a vulnerability** репозитория
(GitHub Private Vulnerability Reporting). Укажите:

- версию (`git describe` или тег образа) и способ запуска (compose, jar, свой прокси);
- шаги воспроизведения или минимальный запрос (без настоящих секретов и данных);
- что, по-вашему, можно получить: чтение чужих объектов, обход политики, отказ в обслуживании, порча данных.

Порядок работы:

| Шаг | Срок |
|---|---|
| подтверждение получения | 3 рабочих дня |
| оценка и план (серьёзность, затронутые версии) | 10 рабочих дней |
| исправление высокой и критической серьёзности | цель — 30 дней |
| публикация | после выхода исправления: запись в [CHANGELOG](CHANGELOG.md) и GitHub Security Advisory, благодарность автору, если он не против |

Проект поддерживается одним человеком; если срок не выдерживается, автор отчёта получает объяснение, а не тишину.

## Что считается уязвимостью

- доступ к объекту, бакету или ключу без права на него: обход подписи SigV4, IAM-политики, ACL, presigned-ссылки;
- раскрытие секретов ключей (в том числе из `credentials.json` при заданном `SECTORIADB_SECRETS_KEY`), данных других объектов, путей хоста;
- порча или потеря подтверждённых данных из-за запроса клиента;
- отказ в обслуживании одним запросом или малым числом запросов, который не ограничивают действующие лимиты ([s3-usage.md](docs/guide/s3-usage.md)).

Не уязвимость, а известное ограничение ([docs/README.md](docs/README.md#известные-ограничения-и-планы)): отсутствие пользователей, ролей и STS, отсутствие TLS в самом сервере (его терминирует прокси),
открытый порт управления, если его опубликовали наружу вопреки [рекомендациям](docs/guide/recommendations.md), работа с `sectoriadb.s3.auth.enabled=false` или `allow-open-setup=true`.

## Как устроена защита

Модель угроз и механизмы — [architecture/security.md](docs/architecture/security.md); чек-лист боевого запуска — [guide/recommendations.md](docs/guide/recommendations.md#чек-лист-перед-боевым-использованием);
внутренние аудиты и их статус — [reports/critical-review.md](docs/reports/critical-review.md). Внешнего аудита безопасности (пентеста) не было.

Проверка зависимостей на известные уязвимости перед каждым выпуском — локально (CI не используется):

```bash
mvn org.owasp:dependency-check-maven:13.0.0:aggregate -DnvdApiKey=КЛЮЧ     # нужна сеть для базы NVD
```

Подробнее — [development.md](docs/guide/development.md). В песочнице, где собран `1.0.0-rc.1`, NVD недоступен: перед окончательным `v1.0.0` проверку нужно выполнить на машине с сетью.

# Журнал изменений

Проект развивался этапами; каждый этап — ветка, растущая из предыдущей (`01-…` → `16-…`). Формат записи: что сделано, что меняется для пользователя, что нужно знать при переносе данных.
Подробное описание этапов — в [docs/history](docs/history/ROADMAP.md); актуальное описание — в [docs/README.md](docs/README.md).

**Общее правило миграции.** Проект экспериментальный: совместимость формата данных на диске между этапами не гарантировалась, миграторов нет. Где формат менялся, об этом сказано ниже; после такого этапа
старое хранилище нужно создавать заново и перезаливать данные. Текущий формат — финальный (блоб `SDBBLOB1` v1, журнал малых объектов `SDBSMOB1` v1, метахранилище `SECTMETA` v1, кодек манифеста v2).

## 16-tls-proxy — TLS через nginx (2026-10-18)

- TLS не реализуется в Java: перед сервером стоит nginx (`deploy/nginx/sectoriadb.conf`, сервис `nginx` в compose, образ `nginx:1.27.5-alpine`). TLS 1.2/1.3, HSTS, редирект `80` → `443`, `Host` и путь без изменений (подпись SigV4 сходится на ключах с пробелами, `+`, `%`, `//`, юникодом и эмодзи),
  без буферизации, тело до 5 ГиБ, `aws-chunked` и `Expect: 100-continue` проходят. Проверено `aws cli`, `rclone`, `s3cmd`, `curl` и `warp` через `https://localhost` ([guide/recommendations.md](docs/guide/recommendations.md#обратный-прокси-nginx)).
- Для пользователей: **порт `8080` больше не публикуется на хост** — клиенты ходят на `https://localhost` (`443`; `80` — редирект). Сертификат кладётся в `deploy/certs/` (в git не попадает); для проверки — `deploy/gen-self-signed.sh`.
  Прежний вариант без TLS и s3manager вынесены в `docker-compose.dev.yml` (`-f docker-compose.yml -f docker-compose.dev.yml`, S3-порт на `127.0.0.1:8080`). Новые переменные `HTTPS_PORT`, `HTTP_PORT`, `SECTORIADB_S3_REQUIRE_SECURE_TRANSPORT`.
- Новое свойство `sectoriadb.s3.require-secure-transport` (по умолчанию `false`, в compose `true`): запрос не по HTTPS получает `403 InsecureTransport`. Схему сервер берёт из `X-Forwarded-Proto` (`server.forward-headers-strategy=native`) только от доверенных прокси (`server.tomcat.remoteip.internal-proxies`, по умолчанию частные сети).
- Условие `Bool` на `aws:SecureTransport` в политиках бакета вычисляется (раньше `Allow` с любым условием не действовал, а `Deny` с условием запрещал всегда); остальные условия — как прежде.
- Формат данных не менялся.

## 13-multipart-metastore — multipart в метахранилище (2026-10-12)

- Состояние multipart — деревья `mpu_uploads`, `mpu_by_bucket`, `mpu_parts`; части — скрытые манифесты; `CompleteMultipartUpload` — одна транзакция без чтения и записи данных (раскладка `MULTIPART`, склейка CRC32/CRC32C/CRC64NVME без чтения данных).
- Для пользователей: `GET`/`HEAD ?partNumber=N` отдают часть (`206`); `Complete` идемпотентен (24 ч); минимальный размер части 5 МиБ (`sectoriadb.multipart.min-part-size`, `400 EntityTooSmall` при `Complete`);
  `ListMultipartUploads` с `delimiter` и маркерами, `ListParts` с корректным `NextPartNumberMarker`; `CreateMultipartUpload` запоминает `x-amz-acl`; `DeleteBucket` отбрасывает незавершённые загрузки; метрика `sectoriadb_multipart_uploads_open`.
- Миграция: формат метахранилища расширен (новые деревья, кодек манифеста v2; старые файлы читаются). Каталог `<data-dir>/.multipart` не читается и удаляется при старте — незавершённые загрузки на момент обновления теряются.
- Сервер больше не импортирует модуль `metastore`.

## 12-modularization — модули и пакеты (2026-10-12)

  `FileStorageService` разбит на `ObjectWriter`/`ObjectReader`/`ObjectCatalog`; тесты-стражи зависимостей; удалён мёртвый код.
- Для пользователей: заголовок `Server: SectoriaDB` у каждого ответа, ровно один `x-amz-request-id`. Форматы, метрики и свойства не менялись.

## 11-review-fixes — исправления по итогам ревью (2026-10-07…2026-10-12)

- Безопасность: анонимный `CopyObject` и не-`private` ACL запрещены; секреты не логируются; ограничения тел (политика 20 КиБ, ACL 64 КиБ, XML 2 МиБ); усиленный парсер `aws-chunked`; `host` и `x-amz-*` обязаны быть подписаны, проверка региона;
  защита от медленных клиентов (таймаут 60 с, минимальная скорость тела, лимиты на ключ); атомарный условный `PUT` (`412`); `PutObjectTagging` честно отвечает `501`; идемпотентный `Complete`.
- Ядро: пул с общим `basePath` отвергается; слот GC освобождается только под затвором загрузок; ошибки метахранилища на граничных случаях; переоткрытие канала после прерывания потока; имена файлов блобов из полного UUID.
- Эксплуатация: логи `INFO` (профиль `debug` для подробных), планировщик в 4 потока, спул загрузок `sectoriadb.upload-tmp-dir` с очисткой при старте, Docker-образ без root, healthcheck на порту управления.
- Новые свойства: `sectoriadb.s3.auth.require-signed-headers`, `enforce-region`, `sectoriadb.s3.limits.*`, `sectoriadb.upload-tmp-dir`, `sectoriadb.multipart.*`, `server.tomcat.*`.
- Изменения для клиентов: `PUT`/`UploadPart` без размера — `411`; клиент, не подписавший `host`/`x-amz-*`, — `403`; медленнее 1 КиБ/с — `400`. Миграции данных нет.

## 10-gc-and-resize — сборка мусора и безопасное расширение (2026-10-07)

- Сборщик мусора возвращает место удалённых и перезаписанных объектов (период ожидания 15 минут, затвор загрузок, обход блобов, компакция `small_*.sob`), команды `gc status|run|sweep|compact`, метрики `sectoriadb_gc_*`.
- `resize` блоба под записью без потери чанков; восстановление записи метахранилища на месте после сбоя коммита (чтение идёт, запись `503`/`507` и возобновляется сама); вытеснение таблиц блобов из памяти по LRU
  (`sectoriadb.cache.*`); барьер долговечности кукушки (без `fsync` под блокировкой таблицы).
- Для пользователей: загрузка, не уложившаяся в период ожидания, может получить `503` и должна повториться; место возвращается не сразу; `blob_*.raw` не уменьшаются. Новые свойства `sectoriadb.gc.*`, `sectoriadb.cache.*`, `sectoriadb.metastore.recovery-backoff`, `sectoriadb.reconcile-on-start`.
- Миграция: форматы не менялись; метки `DELETED` малых записей ставит теперь сборщик, а не коммит.

## 09-multi-blob-pool — несколько блобов в пуле (2026-10-07)

- Групповой коммит метахранилища (запись выросла в 1,25–2 раза); несколько кукушкиных блобов на пул, взвешенное rendezvous-хэширование, индекс чанков `chunks` со счётчиками ссылок (дедупликация по всему бакету с проверкой байт),
  рост пула блобами (`sectoriadb.pool.*`), групповой `fsync` малых объектов, кэш расположения чанков.
- **Миграция:** формат манифеста `CHUNKED` и метаданных изменился (нет `blobFileId`, появился индекс чанков); хранилище предыдущих этапов не читается — создать заново.

## 08-observability-bench — наблюдаемость и стенд (2026-10-06…2026-10-07)

- Метрики Prometheus на отдельном порту `9464`, идентификатор запроса и MDC, лог медленных запросов; стенд Prometheus + Grafana + InfluxDB + node_exporter, нагрузка `warp`, тесты совместимости (ceph/s3-tests, minio/mint), отказов и безопасности.

  метаданные и заголовки multipart, ключи с символами вне BMP, `EntityTooLarge` для >5 ГиБ, `ListObjectVersions` для бакета без версий. Дерево `stats` (число и размер объектов) создаётся при первой записи.

## 07-metastore-integration — метаданные в метахранилище (2026-10-06)

- Пулы, блобы, манифесты и индексы переехали из JSON-файлов в `sectoria.db`; операция S3 — одна транзакция; листинг — диапазонный проход; замена версии объекта атомарна.
- **Миграция:** `pools.json`, `blobs.json`, `manifests/*.json` игнорируются, переноса нет.

## 06-btree-metastore — транзакционное хранилище (2026-10-06)

- Встроенное copy-on-write B+-дерево в одном файле: две мета-страницы, CRC32C страниц, MVCC-снимки, свободные страницы с учётом читателей, проверка `verify()`.

## 05-object-checksums — контрольные суммы объекта (2026-10-06)

- `x-amz-checksum-*` (заголовок и trailer), `Content-MD5`, составные и полнообъёмные суммы multipart, `x-amz-checksum-mode`; CRC32C всего объекта в манифесте и проверка при каждом полном чтении; команды `verify`, `verify-all`.
- Для пользователей: несовпадение суммы — `400 BadDigest`, объект не сохраняется. Манифесты без новых полей читаются (проверка пропускается).

## 04-small-objects — малые объекты (2026-10-06)

- Объекты меньше размера чанка хранятся целиком в append-only журнале `small_*.sob` (CRC32C на запись, восстановление хвоста); пустые объекты — только манифест.
- **Миграция:** новый вид блоба и поля манифеста; старые JSON читались с значениями по умолчанию.

## 03-chunk-integrity — целостность чанков (2026-10-06)

- Формат блоба v1 с заголовком, CRC32C и длиной в 32-байтной записи слота, XXH64-ключи, размер чанка 16 КиБ, проверка на чтении, побайтное сравнение при дедупликации, пересчёт ключа при коллизии, карантин слотов; `scrub`.
- **Миграция:** legacy-формат блобов (9-байтные записи) удалён, старые блобы не открываются (`bad magic`).

## 02-security — безопасность S3-слоя (2026-10-06)

- `public-read` на бакете открывает только листинг (раньше и чтение объектов — **изменение поведения**: анонимный `GET` объектов теперь `403`); явный `Deny` в политиках; проверка `x-amz-content-sha256` и подписей фрагментов;
  отказ всем запросам, пока нет ключей (`allow-open-setup` для старого поведения); XXE закрыт; строгий `uploadId`.
- Новые свойства: `sectoriadb.s3.auth.allow-open-setup`, `sectoriadb.s3.auth.allow-unsigned-payload`.

## 01-engine-safety — безопасность движка (2026-10-06)

- Атомарная вставка в кукушку (путь вытеснений ищется в памяти, перенос с конца), блокировка таблицы, `floorMod` вместо `abs` (формат не менялся), полные чтение/запись в цикле, постоянный канал и `fsync` по схеме «данные → force → метаданные → force»
  (`sectoriadb.fsync`).

# Наблюдаемость

Краткое описание устройства; каталог метрик, PromQL, стенд и алерты — в [руководстве по мониторингу](../guide/monitoring.md).

```
клиент ─► :8080  RequestObservabilityFilter ─► RequestBodyGuardFilter ─► SigV4Filter ─► контроллеры ─► ядро ─► движок / метахранилище
                    │ id запроса, MDC, классификация                                      │ StorageMetrics / EngineListener / MetaStoreListener
                    ▼                                                                      ▼
              S3Metrics (RED)                                              MicrometerStorageMetrics (+ StorageGauges, кэш 15 с)
                    └──────────────► MeterRegistry (Micrometer) ◄─────────────────────────┘
Prometheus ─► :9464/actuator/prometheus   (отдельный Tomcat, без SigV4, S3-фильтры туда не попадают)
```

- **Модульность.** Нижние модули не знают Micrometer: `metastore` отдаёт события через `MetaStoreListener`, `engine` — через `EngineListener`, ядро — через `StorageMetrics` (по умолчанию `NOOP`, в CLI-режиме и тестах);
  сервер реализует интерфейсы на Micrometer. Все счётчики и гистограммы создаются один раз; на горячем пути один `record`; метрики не бросают исключений в движок.
- **RED.** `OperationClassifier.classify(method, uri, query, hasCopySource)` — единственное место, определяющее S3-операцию (по именам параметров, не по значениям; 37 значений `S3Operation`, прочее — `Other`); одна классификация
  для метрик, MDC и логов. Время запроса — от входа в фильтр до последнего байта, отданного контейнеру.
- **Состояние (gauge).** `StorageGauges` пересчитывает значения не чаще `sectoriadb.observability.gauge-cache-ms` из одного кэшированного снимка; ничего не сканируется: слоты ведёт сама таблица, число и размер объектов ведутся
  в транзакциях коммита (дерево `stats`), остальное — `MetaStore.stats()`, несколько `statfs` и небольшое дерево блобов.
- **Кардинальность.** Метки только из закрытых множеств; бакеты, ключи, ключи доступа, `uploadId`, IP никогда не метки (проверяет `S3MetricsTest`).
- **Гистограммы** с явными границами в `Buckets` (запрос 1 мс…60 с, диск 10 мкс…1 с, `fsync` 0,1 мс…5 с, ожидание блокировок 10 мкс…5 с, расширение блоба 0,1 с…30 мин, пауза GC 1 мс…5 с, длина пути вытеснений 0,5…32).
- **Идентификатор запроса.** Фильтр задаёт `x-amz-request-id` (16 hex) и `x-amz-id-2` и закрепляет их (контроллеры не могут добавить второй); MDC `requestId`, `operation` в шаблонах logback; лог медленных запросов — логгер
  `SlowRequests`, `WARN`, без бакета и ключа.
- **Причины отказов аутентификации** определяются в месте отказа и передаются фильтру атрибутом запроса; отказ авторизации (`AccessDenied` по политике/ACL) виден как `sectoriadb_s3_errors_total{code="AccessDenied"}`.
- **Логи:** `INFO` по умолчанию, файл `<meta-dir>/sectoriadb.log`, профиль `debug` для подробного режима — [operations.md](../guide/operations.md).

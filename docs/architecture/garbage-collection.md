# Сборка мусора

Удаление и перезапись объекта освобождают только **ссылки** на чанки (`refcount`). Место возвращает сборщик (`maintenance.gc.GarbageCollector`, `SmallBlobCompactor`; планировщик
`GarbageCollectionScheduler` при `sectoriadb.gc.enabled=true`; те же действия вручную командами `gc …`, [admin-shell.md](../guide/admin-shell.md)). Настройки — [configuration.md](../guide/configuration.md).

## Что собирается

| Очередь / признак | Источник | Что делает сборщик | Условие |
|---|---|---|---|
| `chunk_gc` | `refcount` дошёл до нуля | освобождает слот в блобе, удаляет `chunks`, `chunks_by_blob`, строки очереди | строка старше G; запись по-прежнему с `refcount = 0` |
| `chunk_orphans` | коммит нашёл запись индекса на другой блоб | освобождает слот копии | под затвором загрузок; запись не указывает на этот блоб |
| занятый слот без записи индекса | оборванная загрузка (сбой между записью данных и коммитом, ошибка ACL, `TableFull` посреди файла) | освобождает слот | обход блоба (`gc sweep`), под затвором загрузок |
| `deleted_manifests` | замещённая или удалённая версия | для `SMALL` (и малых сегментов `MULTIPART`): `markDeleted` записи, затем удаляет манифест и строку очереди | строка старше G |
| `small_*.sob` с мёртвыми байтами | пометки `DELETED` | переписывает живые записи в новый файл, переключает манифесты одной транзакцией | доля мёртвых ≥ порога, файл не цель дозаписи |

## Период ожидания G (`gc.grace`, 15 минут)

Мусор моложе G не трогается. Зачем: (1) загрузка, нашедшая чанк с `refcount = 0` в индексе и сравнившая байты, ещё не закоммитила — освобождение слота до её коммита создало бы ссылку на несуществующий чанк;
(2) читатель, идущий по снимку старой версии манифеста, должен дочитать — чанки и запись малого объекта на месте; (3) файл после компакции остаётся до конца G. Загрузка, не уложившаяся в G, не теряет данные:
её коммит получает `COLLECTED` — `503 ServiceUnavailable` с `Retry-After: 1`, клиент повторяет запрос. С `--grace 0s` читатель старой версии получит ошибку (режим администратора и тестов).

## Освобождение чанка — эксклюзивная транзакция

Кандидаты — ключи, чья **самая новая** строка `chunk_gc` старше G (`dueChunks`); пачками по `gc.batch-size` (16) в одной эксклюзивной write-транзакции (`beginWrite`: исключает все коммиты, `replaceBlob` и другие шаги).
Для каждого чанка внутри транзакции перечитывается состояние: строк очереди нет — пропуск; записи индекса нет — снять строки; `refcount ≠ 0` (оживлён) — снять строки; строка моложе границы — не трогать; иначе
**освободить слот** (`freeSlot`: ACTIVE → DELETED, `fsync`, счётчик заполнения уменьшен — веса размещения видят место сразу), затем удалить `chunks`, `chunks_by_blob`, строки `chunk_gc`.
Замороженный `resize` или заменённый блоб откладывается (`gc_deferred{blob_busy}`). Сбой ввода-вывода слота завершает пачку (сделанное фиксируется), проход повторится. За проход освобождается не больше
`max-chunks-per-run` (10 000). Слот освобождается до правки индекса и фиксации: если фиксация не удалась, остаётся запись с `refcount = 0` без слота — безопасно: загрузка при проверке байт не найдёт чанк и перепишет его на месте.

## Затвор загрузок

Копию без записи индекса нельзя освободить «просто так»: загрузка могла получить её дедупликацией внутри таблицы и ещё не закоммитить. `UploadGate` (по одному состоянию на пул):

- Загрузка берёт `Hold` **до** записи первого байта данных и держит до конца коммита (или `abortStaged` при отказе); новая загрузка ждёт лишь пока сборщик осушает/держит затвор (миллисекунды).
- Сборщик (`tryBegin`) запрещает новые `Hold`, ждёт до `gc.sweep-gate-wait` (2 с), пока существующие завершатся, и только тогда освобождает пачку в эксклюзивной транзакции с повторной проверкой каждого ключа по закоммиченному
  индексу. Не успели — пачка откладывается (`uploads_in_flight`), обход пула прекращается.
- `Hold` старше `gc.upload-ticket-ttl` (30 минут) сборщик **отзывает**; отозванная загрузка не может закоммититься (`beginCommit()` возвращает `false`, `COLLECTED`/`503`). Начавший коммит `Hold` не отзывается.

Очереди `chunk_gc` затвор не нужен: у её записей есть строка индекса, а загрузку защищают G и проверка `COLLECTED`.

## Обход блобов (`gc sweep`, раз в `gc.sweep-interval` = 6 ч)

Для каждого кукушкиного блоба пула (не замороженного и не заменённого) страницами по 512 слотов читаются **только ключи** активных слотов (метаданные в памяти), одной читающей транзакцией находятся ключи без записи индекса
на этот блоб, и они освобождаются под затвором. В конце обхода удаляются неучтённые `small_*.sob` (не открытые, без записи реестра, старше `max(G, 60 с)`). Записи `.sob`, на которые не указывает ни один манифест, освобождаются
переписыванием файла.

## Надгробия и малые объекты

Коммит и удаление **не** помечают запись малого объекта `DELETED`: это делает сборщик через G (иначе читатель старой версии получил бы ошибку). Пометка идемпотентна (однобайтовая запись + `fsync`) и выполняется **до**
удаления манифеста; повреждённая запись — ошибка в лог и удаление надгробия. Для `CHUNKED` и `EMPTY` надгробию действий не нужно, для `MULTIPART` помечаются записи малых сегментов.

## Компакция малых блобов

Файл с долей мёртвых байтов ≥ `small-compact-dead-percent` (50) и ≥ `small-compact-min-dead-bytes` (1 МиБ), не являющийся целью дозаписи (`smallAppendTarget`):

1. запечатать (дозапись возвращает `null`, писатели выбирают другой файл) и один раз осушить затвор пула — после этого множество записей конечно;
2. снимок живых манифестов файла;
3. копировать 8 потоками в новый, уже запечатанный файл; каждая запись читается с проверкой CRC32C (повреждённая прерывает компакцию);
4. **обмен — одна транзакция** (`swapSmallBlob`): каждый живой манифест (и сегмент `MULTIPART`) должен стоять на старом смещении и перепривязывается к новому файлу; надгробия старого файла и запись реестра удаляются;
5. файл открывается для дозаписи; старый остаётся открытым и удаляется сборщиком через G (читатели старого снимка читают его).

Блоб `.raw` не уменьшается никогда: освобождённые слоты переиспользуются вставками.

## Таблица сбоев

| Момент сбоя | Что остаётся | Чем кончается |
|---|---|---|
| после записи чанков, до коммита | копии без записи индекса | обход освобождает слоты |
| забытая загрузка (поток не вернулся) | `Hold` в памяти | отзыв по TTL; поздний коммит — `503` |
| слот освобождён, транзакция сборщика не зафиксирована | запись `refcount = 0` без слота | следующий проход: слота нет, записи снимаются; опередившая загрузка перепишет чанк на месте |
| `markDeleted` выполнен, надгробие не удалено | запись DELETED, манифест на месте | повтор идемпотентен |
| компакция упала до обмена | старый файл авторитетен, новый с неучтёнными копиями | обход находит записи без манифестов и переписывает |
| процесс упал после обмена | старый файл без записи реестра | `deleteUnregistered` (старше G и 60 с, не открыт) |
| `resize` замораживает блоб | блоб `frozen` | чанки откладываются на следующий проход |
| бакет удалён при очередях | записи индекса удалены с бакетом | проход не находит строк |

## Решения и ограничения

- Пачка вместо «транзакции на чанк»: две `fsync` на чанк дали бы около 100 чанков/с и блокировали бы писателей; корректность та же — состояние перечитывается внутри эксклюзивной транзакции (`batch-size=1` — строго по одному).
  При задержках `PUT` на пике уменьшайте `batch-size`.
- Выборка `chunk_gc` читает очередь целиком каждый проход (ключ упорядочен по пулу и ключу, не по времени).
- Компакция переключает все живые манифесты файла одной транзакцией: для файла 1 ГиБ из записей по 1 КиБ это около миллиона манифестов; для таких профилей уменьшите `small-object.max-file-bytes`.
- Читатель, держащий старую версию дольше G, может получить ошибку. Слоты карантина и данные блобов, которых нет в реестре, не освобождаются.
- Метрики и алерты — [monitoring.md](../guide/monitoring.md).
